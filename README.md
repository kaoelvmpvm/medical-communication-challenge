# 醫問到底！——病情解碼挑戰 V1.2

Vite + Vanilla JavaScript 的醫病溝通教具。**五人一組、每人一台平板**，四位醫師現場討論、一位病人描述感受，每階段共五回合輪替。教師以自己的裝置管理班級、安排病例、手動記錄正式成績。

沿用 V1.1 的六個虛構教學病例、18 項症狀、人體圖與三階段設計。線索比對不是確診或醫學排除。本版不需要伺服器、雲端帳號、付費 API 或跨裝置連線。

## 啟動與預覽

Node.js 24（見 `.nvmrc`），使用既有 Vite 設定：

```sh
npm ci
npm run dev
```

在執行上述指令的電腦開啟終端顯示的網址，路徑為 `/medical-communication-challenge/`。正式建置預覽：

```sh
npm run build
npm run preview
```

雲端若預設 npm 快取不可寫，可改用 `npm ci --cache /tmp/medical-npm-cache`。網站的三個入口共用同一個網址。

## 課堂操作順序

1. 教師選「教師專用」，輸入固定密碼 **0709**。
2. 新增班級（如 815），新增各組及五個不重複座號；不需要姓名。同班不同組不可重複使用座號。
3. 「病例與病人輪替」會列出每組每階段五回合的病人座號、四位醫師座號與病例碼。每階段從既有六病例中安排五份不重複病例，修改組員不會改動原病例碼或成績。
4. **私下**交付當回合的 12 位數字病例碼給病人；不要向醫師展示教師的安排表。教師可展開查看病例名稱作為判定依據。
5. 四位醫師各在自己的平板選「我是醫生」，選階段及回合。病人選「我是病人」，選相同階段／回合並輸入病例碼。錯碼、錯階段或錯回合不會載入病例。
6. 每位醫師獨立記錄，透過現場討論合作；不會自動同步。教師聽到有效問題或疾病猜測後，手動增加正式提問數；猜對一份病例，手動增加完成數。
7. 下一回合更換病人：學生先回到角色入口選擇新任務，病人取得該回合的新病例碼。更換回合會確認後清空該學生平板的輔助資料，不影響教師紀錄。

### 學生三階段

- **第一階段／聽懂症狀**：醫師自由口頭提問，18 種症狀為未確認／有／沒有三態，可切換或清除。六疾病卡依紀錄比對，線索不一致仍保留灰化卡；不提供問題庫或最佳問題推薦。病人依生活化敘述自行判斷是非，沒有標準真假表。
- **第二階段／問對問題**：醫師從通用題庫選問後念出來；病人在自己的平板選擇「聽到的同一題」，再從四個回答中選擇。確認前可修改，確認後才顯示表達解析。病人將答案口頭告訴醫師；系統**沒有自動傳送回答或同步症狀**。
- **第三階段／說清照護**：病人依人體圖與提示主動描述；醫師可選擇補充問句、整理自己的問題。不顯示競賽分數，也不建立教師第三階段計分表。

醫師端不載入指定病例，也不自行判定猜測正誤；猜測需選疾病並再次確認，計為一次**本機輔助提問**。猜錯可繼續或清空紀錄，輔助提問數保留。學生端的數字不是正式成績，重新整理會清除學生暫存。

## 教師正式紀錄與排名

- 第一、第二階段各自記錄問題數、完成疾病數；切換階段或班級不會混用。
- 有效提問與疾病猜測各算一次；猜錯不歸零。問題數最小為 0，完成數介於 0 到 5。
- 加減按鈕逐次保存，組別列保持固定順序，避免排名變動時連點到另一組。可依組別或座號搜尋。
- 完成 **5/5** 才有正式名次，提問少者優先；同問題數並列，採競賽排名（例如 1、1、3）。未完成者顯示進度，列於正式完成組別後。搜尋不改變全班排名。
- 「復原最近操作」可還原最近一次資料變更，包括加減、組別修改／刪除及一般備份匯入。只保留一次復原，重新整理後不保留復原歷史。
- 刪組及還原備份需確認，沒有一鍵清空整班的操作。

## 保存、備份與隱私

教師資料使用 **localStorage**，每次成功資料變更即以完整驗證過的資料保存；重新整理仍保留，重新進入教師端需再次輸入密碼。鎖定或登出會立即移除紀錄畫面，不把解鎖狀態存入瀏覽器。

- 展開「班級與備份工具」可新增班級、匯出或還原；常用的復原操作維持直接可見。
- 「匯出 CSV」下載所有班級的第一、第二階段成績、座號、進度與名次。使用 UTF-8 BOM、標準 CSV 引號，防止班級文字被試算表當成公式。
- 「JSON 備份」包含所有班級、組員、兩階段成績、三階段病例碼安排。備份是教師的私人檔案，請自行妥善保管，**不要提交到 GitHub**。
- 「匯入 JSON」會先完整驗證、再提示取代目前全裝置班級資料；確認前不變更紀錄。建議先備份。目前支援本專案 `version: 1` 格式、檔案上限 2 MB。
- 儲存空間不足／權限停用時會明示未保存，維持原紀錄；損壞資料不會自動清空，可下載原檔或還原有效備份。
- 同裝置另一分頁已更動資料時，舊分頁會阻止覆寫並要求重新整理。這不是跨裝置同步。
- 清除瀏覽器資料、無痕視窗結束或更換裝置／網站來源可能遺失或無法讀取原紀錄，請定期備份，必要時在新來源匯入。

固定密碼 **0709** 只提供簡易教室管理入口，**不是伺服器身分驗證，無法防止開發工具等技術性繞過**。病例碼是可攜式的情境識別碼，含檢查碼以偵測輸入錯誤，不是加密或安全授權。前端不放真實醫療個資；學生畫面不顯示正確疾病或原始真假表。

## 程式分工

- `src/data/`：原 V1.1 六病例、症狀及通用問題資料；本次未修改內容。
- `src/game/engine.js`：沿用三態及比對邏輯，新增獨立平板工作階段與不自動判分的猜測。
- `src/game/codes.js`：可離線解讀的病例碼與五回合不重複安排。
- `src/teacher/model.js`：班級／組別驗證、計數上下限、正式排名、備份格式及 CSV。
- `src/teacher/store.js`：本機保存、最近一次復原、分頁衝突及失敗回復。
- `src/teacher/controller.js`、`view.js`：教師操作及畫面。
- `src/ui/portal.js`：角色入口、密碼頁、學生回合與病例載入。
- `src/ui/screens.js`、`body-map.js`、`body-lines.js`：沿用醫師卡片與病人人體介面；依獨立平板模式調整互動。
- `src/main.js`：角色隔離與事件；`src/teacher.css` 新增角色／教師排版，沿用 `src/style.css` 視覺系統。

## 測試

```sh
npm test                     # 22 項單元／資料／狀態測試，包含既有 V1.1 回歸
npm run build
npx playwright install chromium
npm run test:e2e              # 5 種尺寸 × 5 項操作驗收
npx playwright show-report
```

已有系統 Chromium 可用：

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

尺寸：1440×900、1024×768 橫向平板、768×1024 直向平板、390×844、375×667。測試包含五個獨立瀏覽器環境模擬五台學生平板、教師保存與備份、六病例／18 症狀回歸及 axe WCAG A／AA 自動掃描。

測試報告及截圖在忽略的 `playwright-report/`、`test-results/`；精選畫面與驗收紀錄見 [V1.2 驗收紀錄](docs/v1.2-validation.md)。畫面證據僅使用虛構座號，沒有真實班級名冊。舊的 [V1.1 紀錄](docs/validation.md) 保留作為歷史資料，不代表本版操作流程。
