# 醫問到底！ V1.5

Vite + Vanilla JavaScript 的醫病溝通教具。**五人一組、每人一台平板**，四位醫師現場討論、一位病人描述感受，每階段共五回合輪替。教師以自己的裝置管理班級、安排病例、手動記錄正式成績。

保留 C01～C06 的原本病情敘述，新增使用者提供的 C07～C12，合計 12 個虛構教學病例、28 項症狀。沿用人體圖及三階段設計；第一階段保留 V1.3 的精簡介面。線索比對不是確診或醫學排除。本版不需要伺服器、雲端帳號、付費 API 或跨裝置連線。

## 啟動與預覽

Node.js 24（見 `.nvmrc`），使用既有 Vite 設定：

```sh
npm ci
npm run dev
```

在執行上述指令的電腦開啟終端顯示的網址，路徑為 `/medical-communication-challenge/`。正式建置預覽：

```sh
npm run build
npm run preview
```

雲端若預設 npm 快取不可寫，可改用 `npm ci --cache /tmp/medical-npm-cache`。網站的三個入口共用同一個網址。

## 課堂操作順序

1. 教師選「教師專用」，輸入固定密碼 **0709**。
2. 新增班級（如 815），新增各組及五個不重複座號；不需要姓名。同班不同組不可重複使用座號。
3. 「病例與病人輪替」列出五回合的病人與四位醫師座號。第一階段由病人平板自行隨機抽取；第二、三階段沿用教師分配的五份不重複病例碼，修改組員不會改動既有成績。
4. 第一階段不分配載入碼，也不自動向教師揭露抽中的疾病；病人頁面顯示固定四位數教材識別碼，教師可自行於「疾病代碼查詢」輸入查核。第二、三階段才需**私下**交付當回合的 12 位病例碼，教師可展開查看這兩階段的安排。
5. 四位醫師各在自己的平板選「我是醫生」，選階段及回合。病人選「我是病人」，選相同階段／回合；第一階段按「開始回合」，第二、三階段則輸入教師病例碼。
6. 每位醫師獨立記錄，透過現場討論合作；不會自動同步。教師聽到有效問題或疾病猜測後，手動增加正式提問數；猜對一份病例，手動增加完成數。
7. 下一回合更換病人：學生回到角色入口選擇新任務。第一階段在確認開始尚未載入的新回合時才抽取；第二、三階段使用對應回合的病例碼。學生操作不影響教師紀錄。

### 學生三階段

- **第一階段／聽懂症狀**：四位醫師輪流口頭提問、口頭猜疾病，病人只回答「是」或「否」。醫師畫面只有12 疾病候選卡、28 張連續網格症狀卡與清空功能；沒有提問／猜測按鈕、本機計數、分類導覽或確認進度。症狀仍可切換未確認／有／沒有及清除，候選卡即時灰化。教師手動登記所有有效提問與疾病猜測。
- **第二階段／問對問題**：醫師從通用題庫選問後念出來；病人在自己的平板選擇「聽到的同一題」，再從四個回答中選擇。確認前可修改，確認後才顯示表達解析。病人將答案口頭告訴醫師；系統**沒有自動傳送回答或同步症狀**。
- **第三階段／說清照護**：病人依人體圖與提示主動描述；醫師可選擇補充問句、整理自己的問題。不顯示競賽分數，也不建立教師第三階段計分表。

醫師端不載入指定病例，也不自行判定猜測正誤。只有第二階段保留疾病選擇與確認、**本機輔助提問**；猜錯或清空症狀不歸零輔助次數。第一階段完全由口頭互動及教師計數，第三階段不計分。學生平板上的數字不是正式成績。

### 第一階段隨機病例與重新整理

病例在病人按「開始回合」且完成必要確認後，由病人平板以 `crypto.getRandomValues` 拒絕取樣，從既有 12 病例等機率選取。每個新回合獨立抽樣，可能再次抽中相同病例，不採五份不重複規則。

抽中結果先寫入該分頁的 `sessionStorage`，成功後才顯示身體圖。重繪、重新整理、取消開始或再次進入同回合不會重新抽取；從病人畫面重新整理會直接恢復原病例。回到角色入口後不會自動露出病情，醫師或教師畫面重新整理也不會恢復病人內容。

此分頁保留本輪第一至第五回合的病例，重返舊回合沿用原病例。要開始全新一輪請另開分頁；關閉分頁、清除分頁儲存或換裝置不保證保留。儲存被停用、額度不足或資料損壞時會阻止開始並提示，不會悄悄丟棄舊病例重新抽取。教師資料仍使用獨立的 `localStorage`，完全不受影響。

## 四態資料、內部疾病代碼與美術圖

病例資料明確保存 `true`、`false`、`unknown`、`not_applicable` 四種狀態；醫師操作仍是未確認／有／沒有三態。只有已設定的 true／false 可以比較衝突，未知及不適用不參與排除。候選卡分別呈現「與線索一致」「資訊不足以比較」「與線索衝突」；「未衝突」數量包含資料不足者，不表示確診。

C07～C12 的 168 個判定值照使用者表格逐項保存；C01～C06 敘述逐字保留，未描述的項目改為 unknown，不再自動填 false。第一階段遇到未知或不適用資訊時，請示意教師判定問題無效並重新提問，**不要編造「否」**；教師可不登記，若已登記可減一或復原。

每個病例都有固定、唯一的四位數「疾病代碼」，例如 C01 的 4726。它是教材內部識別碼，不是 ICD 或醫療診斷碼，**不能當作病例載入碼**。病人顯示代碼而不顯示疾病名稱；教師解鎖後可用「疾病代碼查詢」取得預設疾病名稱及 C01～C12 編號。對應表見 `src/data/disease-catalog.js`，醫師介面不顯示對照表。

第二階段新增眼睛、皮膚、耳朵、胸口與條件式經期問題。經期題只在 C11 病人的選單中出現；其他病例不產生「沒有月經」等虛構答覆，也不推測性別。不適用或未知資訊不能當成確定沒有。最佳回答以病例原文、判定表或提供的摘要為依據，位置有穩定變化，也不是一律最長。

V1.5 整合使用者提供的17張 WebP：首頁 Logo／主視覺、三張角色圖及十二病例圖，原始檔案與路徑完整保留。首頁三張卡各為單一可鍵盤與觸控操作的按鈕，不含巢狀按鈕。病人圖採4:5完整構圖，人體圖仍是主要資訊工具；桌面並排，平板與手機依空間上下配置。缺圖顯示「劇情圖片」，載入失敗也會退回佔位。

Vite 建置時列出 `public/art/` 實際存在的 WebP，以既有 Pages 子路徑產生 URL，不另外打包重複圖片。新增、移除美術後請重新啟動開發伺服器／建置。所有圖片 alt 均不包含疾病答案。頁尾版本由 `package.json` 統一產生，署名「板橋國中 高勳頊老師設計開發」。

## 教師正式紀錄與排名

- 第一、第二階段各自記錄問題數、完成疾病數；切換階段或班級不會混用。
- 有效提問與疾病猜測各算一次；猜錯不歸零。問題數最小為 0，完成數介於 0 到 5。
- 加減按鈕逐次保存，組別列保持固定順序，避免排名變動時連點到另一組。可依組別或座號搜尋。
- 完成 **5/5** 才有正式名次，提問少者優先；同問題數並列，採競賽排名（例如 1、1、3）。未完成者顯示進度，列於正式完成組別後。搜尋不改變全班排名。
- 「復原最近操作」可還原最近一次資料變更，包括加減、組別修改／刪除及一般備份匯入。只保留一次復原，重新整理後不保留復原歷史。
- 刪組及還原備份需確認，沒有一鍵清空整班的操作。

## 保存、備份與隱私

教師資料使用 **localStorage**，每次成功資料變更即以完整驗證過的資料保存；重新整理仍保留，重新進入教師端需再次輸入密碼。鎖定或登出會立即移除紀錄畫面，不把解鎖狀態存入瀏覽器。

- 展開「班級與備份工具」可新增班級、匯出或還原；常用的復原操作維持直接可見。
- 「匯出 CSV」下載所有班級的第一、第二階段成績、座號、進度與名次。使用 UTF-8 BOM、標準 CSV 引號，防止班級文字被試算表當成公式。
- 「JSON 備份」包含所有班級、組員、兩階段成績、三階段病例碼安排。備份是教師的私人檔案，請自行妥善保管，**不要提交到 GitHub**。
- 「匯入 JSON」會先完整驗證、再提示取代目前全裝置班級資料；確認前不變更紀錄。建議先備份。目前支援本專案 `version: 1` 格式、檔案上限 2 MB。
- 儲存空間不足／權限停用時會明示未保存，維持原紀錄；損壞資料不會自動清空，可下載原檔或還原有效備份。
- 同裝置另一分頁已更動資料時，舊分頁會阻止覆寫並要求重新整理。這不是跨裝置同步。
- 清除瀏覽器資料、無痕視窗結束或更換裝置／網站來源可能遺失或無法讀取原紀錄，請定期備份，必要時在新來源匯入。

固定密碼 **0709** 只提供簡易教室管理入口，**不是伺服器身分驗證，無法防止開發工具等技術性繞過**。病例碼是可攜式的情境識別碼，含檢查碼以偵測輸入錯誤，不是加密或安全授權。前端不放真實醫療個資；學生畫面不顯示正確疾病或原始真假表。

## 程式分工

- `src/data/cases.js`：C01～C06 原文、十二病例整合及病人安全資料投影。
- `src/data/additional-cases.js`：使用者 C07～C12 原文、時間／程度等資料、四態判定表及正確回答摘要。
- `src/data/disease-catalog.js`：十二種固定教材識別碼。
- `src/data/symptoms.js`、`questions.js`：28 項症狀、11 類通用問題及條件式適用規則。
- `src/data/art-assets.js`、`src/ui/case-art.js`：依建置清單選圖及無圖佔位。
- `src/game/engine.js`：沿用三態及比對邏輯，新增獨立平板工作階段與不自動判分的猜測。
- `src/game/codes.js`：第二、三階段可離線解讀的病例碼與不重複安排。
- `src/game/random-round.js`：第一階段等機率取樣、同回合保存與還原；不寫入教師資料。
- `src/teacher/model.js`：班級／組別驗證、計數上下限、正式排名、備份格式及 CSV。
- `src/teacher/store.js`：本機保存、最近一次復原、分頁衝突及失敗回復。
- `src/teacher/controller.js`、`view.js`：教師操作及畫面。
- `src/ui/portal.js`：角色入口、密碼頁、學生回合與病例載入。
- `src/ui/screens.js`、`body-map.js`、`body-lines.js`：沿用醫師卡片與病人人體介面；依獨立平板模式調整互動。
- `src/main.js`：角色隔離與事件；`src/teacher.css` 新增角色／教師排版，沿用 `src/style.css` 視覺系統。

## 測試

```sh
npm test                     # 42 項單元／資料／狀態測試，包含原有回歸
npm run build
npx playwright install chromium
npm run test:e2e              # 5 種尺寸 × 11 項操作驗收
npx playwright show-report
```

已有系統 Chromium 可用：

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

尺寸：1440×900、1024×768 橫向平板、768×1024 直向平板、390×844、375×667。測試包含五個獨立瀏覽器環境模擬五台學生平板、教師保存與備份、十二病例／28 症狀回歸及 axe WCAG A／AA 自動掃描。

測試報告及截圖在忽略的 `playwright-report/`、`test-results/`；本次精選畫面與驗收紀錄見 [V1.5 驗收紀錄](docs/v1.5-validation.md)；[V1.4](docs/v1.4-validation.md) 保留作為歷史紀錄；[V1.3](docs/v1.3-validation.md) 保留作為歷史紀錄；[V1.2 驗收](docs/v1.2-validation.md) 保留作為歷史資料。畫面證據僅使用虛構座號，沒有真實班級名冊。舊的 [V1.1 紀錄](docs/validation.md) 保留作為歷史資料，不代表本版操作流程。

## GitHub Pages

沿用原 `vite.config.js` 的 `/medical-communication-challenge/` 與 `.github/workflows/deploy.yml`。依目前授權完成測試後直接提交、推送 `main`，之後執行測試、建置及 Pages 部署；Pull Request 只測試與建置。

儲存庫 Pages 的 Source 需選擇 **GitHub Actions**。部署成功後網址：`https://kaoelvmpvm.github.io/medical-communication-challenge/`。本機建置通過不等於遠端新版已部署，請以 Actions 結果為準。

部署後的 Actions 步驟會逐一要求17張正式圖片 URL 回傳 `image/webp` 並核對附件 SHA-256，任何缺圖或內容不符皆使檢查失敗。可手動執行：

```sh
node scripts/verify-deployed-art.mjs https://kaoelvmpvm.github.io/medical-communication-challenge/
```
