# 醫問到底！V2.0｜P1 學習流程重構

狀態：P1 開發版（僅 `v2-development`；未發布至 `main`）

## 正式入口與動線

`index.html` 在 V2 分支使用 `src/v2/main.js`；V1.6 原始入口與邏輯仍保留在 `src/main.js`，不會影響正式版。

學生流程：
1. 首頁：開始學習挑戰，或教師專用入口。
2. 從四種疾病選擇一種熟悉的模擬疾病：一般感冒、過敏性鼻炎、急性腸胃炎、緊縮型頭痛。
3. 前測：以所選疾病的**同一份固定虛構情境**作答10題。
4. 前測結果：暫用五向度數值與長條呈現。
5. 選擇醫師或病人角色，進入第一階段。
6. 完成第一階段後**直接**進入第二階段；不提供任意選擇階段或第三階段入口。
7. 完成第二階段後進入後測；**沿用前測疾病與固定情境**，回答相對應的後測10題。
8. 完成畫面比較五向度前後測數值，提供確認後重新開始的選項。

教師：首頁「教師專用」→ 原有密碼 `0709` → 保留班級組別、計分與備份，教師介面僅顯示第一、第二階段。原備份中舊第三階段資料不主動覆寫。

## P1 工程界線

- 已完成：新 V2 流程、四種疾病選擇、前後測10題操作、選擇紀錄、同疾病比較、角色入口、兩階段順序控制、教師入口與跨刷新進度保存。
- P2 才做：第一階段以必要資訊與安全醫療決策為核心的邏輯、問答介面、結束條件與計分。
- P3 才做：第二階段五能力資訊的三選一表達練習、完善病例與醫師端UI。
- P5 才做：雷達圖視覺化、正式成果比較。
- 目前 P1 第一、二階段只作**舊介面過渡整合**，實際模擬病例可能不同於個人前後測所選疾病；兩階段完成按鈕暫為手動跳轉，之後由 P2、P3 規則取代。不得宣稱已完成新版醫療決策。
- 完整 V2 正式發布前仍須逐字覆核80題內容、完成專業醫療判準審核及跨平板驗收。

## 資料保存與邊界

- 使用 `sessionStorage` 鍵 `medical-challenge-v2-learning-v1`，與 V1.6 教師計分 `medical-challenge-teacher-v1` 分離。
- 同一台平板重整頁面可恢復角色、已選疾病與前後測答案；當前過渡的醫師／病人操作紀錄**不**會保留，之後 P2/P3 再補完整保存。
- 若資料損壞，不自動覆蓋；提供使用者確認清除的控制。
- 不蒐集學生真實病史，病例均為虛構。
- 不使用同步或伺服器：各平板彼此獨立，教師手動競賽紀錄另行保存。
- 學生在前測選擇疾病後，不能中途更改；僅能完成流程或確認重新開始。
- 作答時不顯示分數、標準答案或判分理由。

## P1 測試驗收

1. 四種疾病均能完成前測→第一階段→第二階段→後測→結果。
2. 每次測驗需完成10題才能送出，題目與選項ID正確。
3. 不可跳過前測、變更疾病或在未完成的階段先進入後測。
4. 前後測必須屬於相同疾病，原始負分保存，畫面分數限定0～4。
5. 不存在第三階段導覽入口（包含教師端）。
6. 正式 V1.6 的 `main`、網址與原始內容不改動。
7. 單元測試與 Vite 建置通過；Playwright 實際平板測試留待整合驗收。

此文件作為 P2/P3 後續重構時的流程與狀態契約。
