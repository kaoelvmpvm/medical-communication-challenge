# V1.3 第一階段局部調整驗收

以已合併 PR #1 的 `main`（`b45170e`）為基礎，於新分支 `codex/stage-one-v1.3` 開發。不重建專案、不修改六病例原文與證據、不變更 Vite 或 Pages 設定。

## 本次結果

- 單元測試：28 項通過，0 失敗、0 略過。
- Playwright：30 項通過，0 失敗、0 略過，涵蓋五種指定尺寸。
- 正式建置及 `git diff --check` 通過。
- 主要畫面的 axe WCAG A／AA 自動掃描通過；不宣稱完整人工無障礙認證。

## 修改範圍

- 第一階段醫師端移除提問、猜測、手機快捷、症狀分類、確認進度與本機計數，保留六疾病及18張可操作症狀卡；清空功能移至紀錄標題旁。
- 連續症狀網格：橫向平板四欄、直向三欄、手機兩欄，極窄畫面一欄。有／沒有按鈕同時使用綠／紅色、圖示及文字。
- 第一階段病人無病例碼欄位，正式開始新回合後在病人端等機率抽取。以拒絕取樣避免 uint32 模數偏差，原病例內容不變。
- `sessionStorage` 在顯示病情前保存結果。同回合重繪、重新整理、取消或重複開始不再抽取，重返舊回合也沿用原病例；不同新回合可以重複抽中同一病例。
- 重新整理只在原本正顯示第一階段病人畫面時恢復；切至角色入口、醫師或教師後不會自動顯示病情。儲存失敗或損壞時阻止開始，不悄悄重新抽取。
- 教師第一階段只顯示座號輪替，不顯示病例碼及安排中的疾病名稱。舊備份格式與欄位保留相容，不遷移或清空教師紀錄。
- 第二、第三階段維持原病例碼、題庫、回答解析、補充詢問及教師紀錄流程。

## 測試

```sh
npm test
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

28 項單元測試包含均等取樣、拒絕邊界、五回合保存、重複開始／還原、損壞與額度失敗，以及第一階段移除項目；亦保留既有病例、狀態、教師保存與計分回歸。

Playwright 在 1440×900、1024×768、768×1024、390×844、375×667 各執行六項整合驗收，包含：

1. 教師 PIN、班級、組別、座號檢查、刪除與復原。
2. 第一／二階段正式計分、排名、本機保存、CSV 及 JSON 匯入還原；第一階段沒有病例碼，第二階段仍有五份有效病例碼。
3. 六病例原文與人體圖（透過第二階段既有碼逐一驗證）、18症狀三態、即時候選篩選、第一階段清空，以及第二階段猜測功能。
4. 四醫師與一病人的獨立平板、第二階段選問與回答、第三階段補充詢問。
5. 第二／三階段病例碼錯誤與教師儲存失敗處理。
6. 第一階段無碼開始、抽樣次數、重新整理保持原病例、取消不抽樣、正式新回合才抽樣、重訪沿用舊病例及保存失敗不呈現新病例。

主要畫面另執行 axe WCAG A／AA 自動掃描、觸控操作、水平溢出及卡片重疊斷言。瀏覽器測試可控地替換隨機來源以避免機率造成測試不穩定，正式程式沒有測試用選病例入口。
