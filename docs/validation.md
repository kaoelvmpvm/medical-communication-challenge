# V1.1 驗收紀錄

## 範圍

從 V1 的靜態首頁與三階段模組骨架建立同裝置雙角色可操作教具，保留 Vite 子路徑、GitHub Pages 工作流程與三階段順序。原版沒有病例或計分實作，因此新增六個虛構教學病例，不新增競賽分數公式。

## 自動驗證

- `npm test`：12 項通過，0 失敗、0 略過。
- `npm run build`：成功。
- Playwright / Chromium：16 項通過，0 失敗、0 略過。
- 裝置配置：桌面 1440×900、平板 1024×768、手機 390×844、小手機 375×667。
- 主要畫面 axe WCAG A／AA 自動掃描：沒有違規。另實際驗證鍵盤交接、對話視窗初始焦點／Escape 返回、感受卡定位及觸控。

| 驗收項目       | 驗證內容                                                                               |
| -------------- | -------------------------------------------------------------------------------------- |
| 六病例人體標註 | 各病例原文與框數一致、錨點對應部位、桌面連接線終點與標記中心誤差小於 2px               |
| 響應式布局     | 四種尺寸檢查頁面水平溢出、感受卡／症狀卡／候選卡／選項／部位按鈕彼此不重疊，並檢視截圖 |
| 18 種症狀      | 每一項逐一未確認→有→沒有→清除，重複點按保持選擇狀態                                    |
| 候選案例       | 各症狀正反條件即時更新，包括零符合與清除後恢復六張；保留灰化卡片                       |
| 第一階段       | 沒有題庫、自由口頭提問計數、沒有病患原始答案                                           |
| 第二階段       | 六類問題、四個不同回答、修改選擇、確認前不顯示解析、送出後鎖定、醫師讀取已確認回答     |
| 第三階段       | 描述提示勾選、角色輪替、完成確認；沒有猜測或提問／競賽計分欄位                         |
| 資訊隔離       | 交接時兩角色 DOM 都不保留；病患 DOM 無疾病名稱或真假表；醫師 DOM 無原始病情標註        |
| 重來與進度     | 猜錯及清空保留提問數、對話歷程；下一病例重新記錄，六病例後可進下一階段                 |
| 部署           | 正式建置資源使用既有子路徑；未修改原有 Pages 工作流程及 Vite 設定                      |

## 已知限制與未宣稱完成的項目

- 未提供跨裝置同步、登入授權、持久儲存或競賽排行榜；這些不是原有功能。
- 同機交接可隔離可見介面，無法阻止使用者用開發工具讀取前端虛構病例。
- axe 與鍵盤檢查不等同完整 WCAG 認證；尚未進行真實 iOS／Android 裝置或真人螢幕閱讀器使用者測試。
- 兩張示意圖未附於本次對話；資訊架構依文字規格實作。
- 正式 GitHub Pages 是否可開啟取決於提交是否合併至 `main`、儲存庫 Pages 設定與遠端 Actions 結果；本次本機測試不能證明線上已部署新版。
