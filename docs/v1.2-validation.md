# V1.2 多平板與教師紀錄驗收

## 與 V1.1 的關係

以工作分支的 `da26bdf` 為基礎接續開發，未重設或覆寫未合併提交。沿用病例資料、18 症狀、三階段 ID／順序、人體圖及視覺系統；Vite 和原 Pages 工作流程不變。原同機交接改為五位學生各用平板、口頭互動及教師提供病例碼。

## 本次結果

- `npm test`：22 項通過，0 失敗、0 略過，包含原 V1.1 的 12 項回歸。
- `npm run build`：成功。
- Playwright／Chromium：25 項通過，0 失敗、0 略過。
- 五種尺寸的主要畫面 axe WCAG A／AA 自動掃描沒有違規。

## 重現方式

```sh
npm test
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

若尚未安裝 Chromium，先執行 `npx playwright install chromium`，再用 `npm run test:e2e`。

Playwright 配置為 1440×900、1024×768、768×1024、390×844、375×667，每個尺寸執行五個整合測試。實際結果與截圖以當次報告為準：`npx playwright show-report`。

## 明確限制

- 固定 PIN 與病例碼不提供真正身分驗證或資料加密；不阻止開發工具讀取前端病例。
- 沒有跨平板同步、伺服器、雲端帳號或自動正式判分；現場對話與教師手動紀錄為正式來源。
- 教師資料只在該裝置／網站來源保存；瀏覽器資料清除或裝置故障仍可能遺失，需由教師下載備份。
- 自動掃描和模擬觸控不等同真實平板、螢幕閱讀器或完整 WCAG 人工認證。
- GitHub Pages 新版部署必須先合併至遠端 `main` 並成功執行 Actions；本機驗證不宣稱線上已部署。
